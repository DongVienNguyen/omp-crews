# Ma trận micro-task — 27 mục của đề xuất

Các route dưới đây là default đề xuất khi facts đúng, không phải quyền ép model theo từ khóa. Governance hợp lệ có thể nâng/điều chỉnh mapping trong phạm vi an toàn; report giữ baseline và effective khác nhau. `stage` không đổi semantics tám need. `Small/Auto` vẫn tính effort riêng theo difficulty, không mặc định low. Không xác minh được tên thương mại/provider backend trong đề xuất; giữ Combo user-configurable.

| ID / stage | Micro-task gốc | Route đề xuất và điều kiện |
|---|---|---|
| D1 Discovery | Quét cây/tìm function/component/biến bằng regex | Dùng glob/grep/LSP/CodeGraph nếu index tồn tại; cần worker tổng hợp facts thì research / bounded_retrieval / Small. Symbol search dùng LSP khi có server, không scan source vô hạn. |
| D2 Discovery | File>500dòng → signatures map | AST/LSP/native declarations trước; research / bounded_retrieval / Small nếu cần map có source anchors. Không đọc full file chỉ do vượt500dòng, không để summary mất side effects/invariants. |
| D3 Discovery | Đọc dependency versions và env mẫu | research / bounded_retrieval / Small; chỉ package/lock/.env.example đã cấp quyền, không đọc .env thật hoặc credential values. Version compatibility judgment chưa rõ chuyển Medium/Large phù hợp. |
| D4 Discovery | API docs/OpenAPI → endpoint liên quan | research / bounded_retrieval / Small nếu endpoint/scope rõ; lưu nguồn/version/params/errors. Chọn protocol/auth/consistency chưa rõ là design, không retrieval giả. |
| A1 Architecture | Schema DB, index,1-n/n-n | research / integration_architecture / Large khi phải quyết định schema/contracts/consistency. Apply schema đã duyệt theo mẫu → Medium implementation, migration an toàn vẫn acceptance/risk gate; không chạy production migration tự động. |
| A2 Architecture | Auth/JWT/OAuth/RBAC/payment | research / integration_architecture hoặc difficult_review / Large cho quyết định seam/security; producer Medium triển khai spec chốt; Large independent security/data-loss review trước delivery. Không gửi secrets cho scout. |
| A3 Architecture | Spec/phân rã feature>=4file | Nếu undecided interfaces/risk mới Large architecture; nhiều file nhưng seams đã rõ → Medium implementation plan. Spec nêu acceptance, source constraints, read/write/command budget, stage dependencies; không tự tạo quyền mới. |
| A4 Architecture | API request/response/errors | Medium / everyday_implementation cho contract CRUD quen thuộc; tương thích giao thức/cross-service semantics chưa chốt → Large architecture. Không dùng required/optional suy từ một JSON mẫu. |
| S1 Scaffolding | JSON→TS/interface/Zod/Yup | produce / repeatable_task / Small chỉ khi null/optional/coercion/defaults/error rules và template đã cố định; còn quyết định validation → Medium everyday_implementation. Check độc lập schema behavior, không test copy text. |
| S2 Scaffolding | Mock/Faker/DB seed | produce / repeatable_task / Small khi schema, constraints, cardinality, data giả và deterministic seeds đã chốt. Viết logic seed mới Medium; execution chỉ temp/test DB explicit, không seed production hay dữ liệu cá nhân. |
| S3 Scaffolding | Tạo file/controller/component theo mẫu | Small prescribed generation nếu thực sự cần và target/template rõ. Không commit component rỗng/TODO/no-op; dùng generator có sẵn trước. Small prefix không bắt buộc nếu Medium làm cùng logic sẽ rẻ hơn qua một lượt. |
| S4 Scaffolding | HTML/CSS/design→JSX/Tailwind | Small nếu mechanical syntax/pattern conversion có tiêu chí fidelity và AX cố định; layout/design/interaction/responsive/AX cần quyết định → Medium. Visual smoke trên surface thật, không chỉ compile. |
| I1 Implementation | UI state/effect/handlers/form | produce / everyday_implementation / Medium; exact local patch có thể Small bounded/routine với checker. Unknown stale-state cause tách discovery và Large diagnosis nếu cần; không dựa vào1–3file để hạ risk. |
| I2 Implementation | Backend/service/ORM/response | produce / everyday_implementation / Medium; trust-boundary validation/errors giữ đủ. SQL injection/auth/data-loss review riêng Large theo risk. Prescribed mechanical DTO patch Small khi facts thật. |
| I3 Implementation | Fetch/loading/error/optimistic UI | Medium implementation khi contract đã chốt; concurrency correctness hoặc rollback invariant chưa biết Large thiết kế/diagnose đoạn khó. Test cancellation/stale response/error semantics, không chỉ happy path. |
| I4 Implementation | DB→API→UI theo plan | Medium / long_running_agentic cho một outcome liên kết qua nhiều stage; tách producer artifact owners khi chạy độc lập. Stage DAG/waves không giao cùng file cho hai writer; end-to-end invariant checker. |
| I5 Implementation | WebSocket/SSE/queue/financial/regex | Known wiring theo spec Medium; exact generated mapping Small nếu đủ; intrinsic algorithm/precision/concurrency correctness cô lập Large producer/specialist với capability_reason rõ. Trước khi có failed attempt, không khai báo giả đã thất bại chỉ để đạt specialist; phase1 cập nhật rubric thống nhất. |
| V1 Verification | Log compiler/lint/import và sửa | Tool chạy command trước; check / mechanical_verification / Small tổng hợp diagnostics. Sửa là producer khác: prescribed edit→repeatable_task Small; named code fix còn quyết định→everyday_implementation Small guard hoặc Medium. Checker không bao giờ ghi file; lỗi type có nguyên nhân semantic chưa rõ Large diagnosis. |
| V2 Verification | Output/schema/casing mismatch | check / mechanical_verification / Small khi schema/criterion cố định. Repair actor riêng. Vấn đề version/authorization/serialization contract cần judgment không gọi mechanical. |
| V3 Verification | Viết unit/integration test và self-heal loop | Medium implementation cho test logic hoặc long_running_agentic khi kết quả các vòng liên kết. Independent check/immutable profile ngoài producer scope; tối đa2behavioral repair attempts cùng fault trước Large. Không để producer tự đổi oracle/skip/xóa assertion để đạt PASS. |
| V4 Verification | Logic sai/button không ăn/state trễ | Medium implementation nếu nguyên nhân và hành vi cần sửa đã xác định. Unknown root cause tách research facts Small rồi difficult_review Large, dù1file. Sau fix phải exercise đúng surface, không nhận self-COMPLETE. |
| V5 Verification | Medium2repairs fail / race/leak/deadlock | Large specialist khi lịch sử sửa nghiêm túc cùng fault không thành công; unknown severe/risky diagnosis Large ngay không đợi2. Host ghi immutable attempts/fault lineage; không reset bằng run/role mới. Provider/schema lỗi không là behavioral strike nhưng vẫn tốn cap/resource budget. |
| O1 Optimization | Extract/rename/refactor1file | Native LSP/codemod khi hợp; Medium implementation nếu chọn decomposition. Exact rename map + symbol-aware verified change có thể Small. Public semantic refs và runtime invariant phải được kiểm tra; không refactor vì “clean” ngoài scope. |
| O2 Optimization | SQL N+1/UI re-render perf | Profiling/query plan/log extraction Small; known cause + known patch Medium; uncertain optimizer/complex performance tradeoffs Large difficult_review/specialist tùy history/capability. Đo workload trước/sau, không mặc định mọi optimization là specialist. |
| O3 Optimization | SQLi/XSS/CSRF/IDOR/key/data-loss | Check / difficult_review / Large cho semantic/security judgment; deterministic secret pattern scan có thể Small/tool, không được tự chứng nhận không có lỗ hổng. Original risk acceptance và independent proof giữ riêng producer. |
| C1 Closure | JSDoc/README/CHANGELOG | Small repeatable khi facts và wording/mapping template được chốt; viết thông tin mới/thiết kế tài liệu Medium implementation. Không claim unrun check, không docs secrets, không tạo changelog nếu repo không yêu cầu. |
| C2 Closure | Diff→commit message/PR description | Small repeatable nếu template/scope/facts đã định; cần judgment mapping impact → implementation/appropriate review. Diff có thể chứa secrets: sanitize trước. Commit/push/PR chỉ khi user đã cấp quyền, không tự publish vì tới stage7. |

## Bảy stage không phải bảy lần model bắt buộc

- Lookup một version: D3, tool hoặc Small, kết thúc; không architecture/scaffold/producer/checker dư thừa.
- Exact DTO change: D1 nếu cần → S1 producer Small → V2 deterministic check Small/tool. Không trả giá Large vì có policy review background tính chung thành task.
- Feature CRUD: D1/D4 theo nhu cầu → A4 Medium → I2/I3 Medium → V2/V3 independent behavior check → C1/C2 nếu requested. Large không có business-task check mặc định nếu risk thấp.
- Auth/payment: D1/D4 Small facts → A2 Large decisions → I2/I3 Medium; template Small nếu đáng tách → V3+O3 independent Large → delivery. High-risk route quyết định bởi facts, không keyword-only.
- Retry chain: V2 Small findings → producer Medium repair1 → immutable check → repair2 nếu còn cùng lỗi → immutable check → Large diagnosis/repair theo cap; không thêm repair3 ở Medium.
