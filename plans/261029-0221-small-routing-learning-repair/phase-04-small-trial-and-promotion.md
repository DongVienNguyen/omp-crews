# Phase4 — Learn Small ability by executing Small

P1; depends phase3. [Evidence F4/F5/F6/F9](evidence.md). No mandatory task experiments before operator trial consent.

## Design

Use existing immutable workflow + native admission for trial; no alternate agent SDK or background replay. Each opportunity reviewed with original acceptance/profile meaning and frozen authority. Medium baseline evidence selects opportunity, Small trial supplies competence. Host decides state transitions; model only proposes typed metadata.

Reuse exact grant/job/frozen artifact authorization; no ad-hoc agent launcher. Trial identity binds issue/family/original source/checker/acceptance/model-policy version. Cancelled or historical failed run cannot be replayed as trial; trial is explicit new isolated snapshot with frozen starting state and separate budget.
2. No missing facts converted false, no arbitrary complexity expansion or generic need->Small rule.

No new monetary gate; token/attempt/latency coverage reported. Snapshot source/config pinned (existing immutable harness) and oracle outside writer grants. 5. Trial pass/fail/unknown appended immutable; original invariant and normal/error/boundary oracle independent. 7. Audit transition explicit: due reservation creates one host-owned audit-delivery token under same trial consent and approved Small binding, not an ordinary learned hit and not Medium fallback. At most one such Small producer plus independent checker runs on current immutable snapshot; fresh success clears audit_pending and completes that delivery without a second reservation. Audit-only proof never trains; unknown/fail/drift suspends. Concurrent reservations blocked; cancel consumes attempt cap, no replay. At audit_every=1 every use is this checked audit delivery, so usable but no claim of cheap efficiency. Regression must prove cadence1 and10, concurrency, repeat token, pending starvation, Small model binding and checker failure. Exact field/state names follow existing grant/job/token conventions; no model-created audit authorization.

## Effectiveness evaluator — selected owner and contract

Extend existing `crews/workflow_evaluation.py` with a separately signed capability-comparison operation, not recipes._probe and not a loosened ordinary workflow report. Preserve ordinary monetary/quality_only schemas. New manifest pins original unit/source groups/initial artifacts/criteria/profile/environment/provider-model policy and per-arm executed role bindings: baseline Medium, candidate Small, same independent oracle/checker rules. Different arm models are intentional treatments declared before execution; each native receipt must equal its own frozen Combo/model/effort, never recipe.model_binding for both sides. No force policy bypass: explicit trial authorization is separate from production route.

Reuse phase2 canonical attempt pair proof. Both arms must deliver original independent behavior pass, no per-unit regression/false completion/unknown, equal before/acceptance/profile and resource conditions. Components include orchestration/scout/producer/checker/governance/recheck and failed attempts. No monetary/priced accounting requirement. Freeze efficiency objective BEFORE runs: token-primary requires complete provider input+output totals, candidate strictly lower, attempts<=baseline and host P95<=baseline*1.20; latency-primary requires candidate host P95 strictly lower, attempts<=baseline, and token<=baseline*1.20 only when complete. If token coverage missing under latency-primary, report token efficiency unknown and qualify latency-only benefit, never token/saving claim. No switch objective after results. Equal pass/no measured benefit returns no_measured_benefit. Comparison verdict cannot activate recipe; competence still actual Small proof under thresholds.

Expose capability comparison through versioned `crews/sdlc_api.py`, `omp_bridge.py`, `omp_server.py`, catalog and CLI schemas, preserving ordinary workflow and legacy signed recipe-probe behavior. Existing `recipes._probe` cannot be used for Medium-vs-Small; return explicit unsupported comparison error pointing to new operation, never falsify same model binding/price. Acceptance: Medium pass+Small pass+preselected measured benefit qualifies; no benefit doesn't; mixed-arm receipt, faster but wrong behavior, missing failed-attempt coverage, oracle/source drift, reused holdout reject. New trial/evaluator consent uses existing signed admin path initially, separate from keyless Large policy authority; signer remains operator-owned and model never sees private key. Real Small competence evidence keeps original Small binding.

## Acceptance

Real provider: one previously Medium frontier family Small trial and independent cross-node executable checker, native/wire/host proof; later hit only after proper promotion threshold. One trial alone is not activation evidence; threshold tests use isolated deterministic fixture outcomes, never claimed real59independent successes. Negative cases: difficulty>1.5, files>3, missing facts, risky/unknown cause, failure, unknown, oracle writable/modified, source repeat, holdout leak, model revision drift, explicit floor, no consent, cap exhausted reject. Effectiveness metric: fewer Medium executions for same supported accepted behavior, no false accepts or hidden delivery/latency inflation. If trial overhead exceeds benefit, keep baseline and disable frontier trials; don't chase Small share.
